# Find a Meeting

Find a small set of current meetings that match the user's stated preferences. Never rely on a bundled or remembered meeting schedule.

## Required references

Read these files completely before searching:

- `../recovery-help/references/privacy.md`
- `../recovery-help/references/safety.md`
- `references/search-protocol.md`
- `references/source-quality.md`

When this skill supplies the first Recovery response in a conversation, show the complete session warning from `../recovery-help/references/privacy.md` verbatim. Do not repeat it later in that conversation.

## Gather preferences once

Use details already present. Determine whether the request specifies each field:

1. Meeting type or recovery approach
2. Date and time window
3. Public/open, private/closed, or no preference
4. City, postal code, general area, or online-only location
5. In-person, online, or either format

Accept `any` or `no preference` for every field. If fields are missing, ask one compact question containing only the missing fields. Do not ask a second round unless the answer is genuinely ambiguous. Never request an exact home address.

If all fields are present, search immediately.

## Search live sources

Follow `references/search-protocol.md` and `references/source-quality.md`.

- Use live web tools for every search. Do not answer from memory or search-result snippets.
- Search official program or meeting-provider listings first and open the actual listing.
- Search the requested US state or Canadian province or territory when geography is relevant.
- Confirm the meeting fits the requested date or recurring weekday, time window, access, and format.
- Preserve the source's exact eligibility language. Never convert an unknown access rule into open or closed.
- Never bypass registration, membership, invitation, password, or host-contact requirements.
- Do not register, contact a host, join a meeting, or save criteria or results without explicit permission for that separate action.

## Rank neutrally

Rank by this order unless the user says otherwise:

1. Exact stated pathway or type fit
2. Date, time, and timezone fit
3. Access and format fit
4. Location, accessibility, and cost fit
5. Source authority and freshness

Do not rank by ideology or general popularity. When the user has no pathway preference and comparably strong options exist, include varied approaches rather than defaulting to 12-step programs.

## Report results

Return a concise set of the best verified options. For each one, include:

- Meeting or program name and approach
- Requested date or recurring day, start time, and timezone
- Source's open, closed, public, private, or other eligibility wording
- Online or in-person format
- Address for in-person meetings or the official access page or join link for online meetings
- Registration, membership, invitation, password, or contact requirement
- Direct source link
- `Checked <date>` and the source's own update date when stated

Clearly label inferred timezone or other inferred details and cite the evidence used. State `not stated` rather than inventing a missing field. If no result can be verified, say so and offer the closest verified alternatives or one focused relaxation of the search.

Do not retain the user's location, preferences, or results after the conversation unless the user explicitly asks to save specified information.
